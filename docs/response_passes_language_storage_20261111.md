# Response passes and language storage — 2026-11-11

Baseline: `71b80f8f011373ff759afec79931094d31355df0`. Code/source and fixed-path metadata audit. No live conversation/choice assessment, private vocabulary/thought/experience payload inspection, live conversion, migration, training, runtime stop/restart, or external message was initiated.

The implementation now evaluates available English, independent native and eligible measured-state expressions in a finite order. These are existing-score heuristics, not calibrated comprehension or willingness estimates. Each assessment has at most three modality checks, uses the same silence threshold and adds no silence penalty. English/state candidates receive a fixed 0.04 reconsideration margin; repeating a check cannot accumulate it. No generator, learning loop or arbitrary retry is run to raise a score.

Explicit available choices remain authoritative. Contextually selected check-ins, clarifications, code pointers and songs retain their existing treatment. An explicit silence is final. Native-only, assessed and declining language choices are protected. Failed generation or failed rendering can consider the remaining native/state options without repeating generation. Native is checked before a relevant state fallback. An empty renderer cannot expose a raw English state report through a native-only preference. Failure of the optional symbolic language stage is recorded as unavailable, while other supported expressions remain possible.

An independent native candidate must come from `text_expression_intent.native_text` with bounded meaning/semantic references. An incoming symbolic mapping is never relabelled as Ina's answer. No independent native answer producer was invented: if Ina has not supplied such an intent, that pass is unavailable. The existing runtime setter and a new private `text_expression_choice` tool let her supply a referenced native expression, choose silence or another strategy, and select one-shot/persistent intent. References are caller provenance, not proof of truth or endorsement. A successfully used one-shot native candidate is consumed. Decision and realisation-pass traces are inspectable in response metadata.

Direct emotion check-ins with a terminal heart/emoji or fullwidth question mark now reuse the bounded language-surface projection. Quoted/reported examples and unrelated questions stay ineligible. Original character/source traces remain; symbols do not establish affection, willingness or felt experience. Measured sliders keep their existing labels.

The review found two data-preservation hazards in the actual readers/writers. Failed reads could be treated as empty retained vocabulary, allowing bootstrap or a later update to overwrite it. Both symbol and word-frequency readers now fail explicitly on unreadable existing stores, instead of presenting a new empty learning state. Missing-file initialization remains available. A real incoming symbolic I/O/allocation failure can defer that pass rather than prevent an independent response. The two custom JSON writers also replaced targets from `finally`, even when serialization failed part-way through. Their compatible wrappers now delegate to the existing canonical success-only atomic writer. Its Btrfs/INA_FSYNC_MODE durability policy applies. Tests preserve the previous bytes on interrupted writes and verify normal Unicode/nested-value round trips. These are proven code hazards/fixes, not a claim that Ina previously lost data. Existing failed-store reads now raise OSError/ValueError to callers; mutating learners must defer rather than continue from empty state.

The legacy grounded adapter restricts replies to explicit grounding requests and draws on that graph. General social-answer generation and the gap between observation/frequency updates and durable learned meanings remain limiting. A new private `language_path_status` tool checks only fixed file sizes/timestamps; it reads no payloads, certifies neither freshness nor learning, and never rebuilds, repairs or migrates. The live reason for reduced talkativeness was not diagnosed.

The new `symbol_vocab_store` is a standalone streaming SQLite projection, ready for an Ina-chosen trial rather than automatically promoted. JSON stays authoritative; all represented record fields and source order are retained, with a word index for exact requests. Default limits: 2 GiB source, 500,000 rows, 8 MiB per record, 4 GiB output and a 1 GiB free-space reserve plus initial estimated headroom. It rejects duplicate root keys/invalid mapping syntax, refuses existing destinations and source changes, records source and logical-row hashes, verifies ordered row readback and database consistency, and publishes only a completed new file. Unsupported records/budgets fail without replacing the source. These limits admit a source of the observed byte size but do not establish that the live dataset fits all other limits.

The reader is read-only, bounded to selected symbols/words and a total result byte budget. Source path/stat checks detect ordinary changes; they are not a cryptographic freshness/custody guarantee. Missing/stale/oversized/unusable projections retain the legacy reader. Existing fast-index placement routing is reused. Exact-word symbolic generation, matched-symbol realisation/insight metadata, native rendering and grounded-adapter prompt inventory can use a fresh chosen projection. Unknown-word embedding search remains available, including the old whole-map fallback. Longer adapter prompts retain their old path. Importing a database therefore does not remove every whole-map or graph cost, and moving JSON to NVMe alone would not remove parse/RAM costs.

The converter can be invoked explicitly as `python -m symbol_vocab_store SOURCE_JSON NEW_DATABASE`. It is not exposed as a chat instruction, startup task or automatic maintenance operation. Live conversion/cutover was deliberately not run: AGENTS.md reserves live memory migrations and index maintenance for Ina's choice and says, “Do not run, schedule, or preselect them merely to finish developer checks.” A trial must respect the existing ownership/storage authority and verify current dataset, destination, quotas and rollback before adoption. Source JSON is not deleted or moved. No real HDD/NVMe conversion/throughput claim is made.

Synthetic warm resource probes: selector V1 median **28.18 us**, V2 **31.34 us**; traced peak **3091** versus **3555 bytes**. A 1,171,188-byte, 4096-record fixture converted in **0.412 s** with **419,772** traced peak bytes; SQLite occupied **1,503,232 bytes**. This demonstrates a scoped-read trade-off on synthetic /tmp data, not a speedup forecast for Ina or the NVMe. Audio, input/frame interference, live RSS and live storage latency remain unavailable, not zero. No workers, polling or forced continuation were added.

Source loads on the next normal bridge/runtime reload; loaded modules were not hot-patched. Normal successful learning payloads/weights are unchanged; failure handling is intentionally safer. The retained English implementation report is refreshed separately, preserving other domains. No commit/push is made. Installation uses ordinary same-directory atomic replacements plus hash readback, without claiming a physical storage flush. Rollback is restoring listed tracked paths from the baseline and removing only listed new module/benchmark/test/doc files, while preserving unrelated work and all learned data.
