# Ina Radio — 2026-10-21

The station is implemented and installed, off-air. The verified local preview is `http://127.0.0.1:8787/`. The intended public address is `https://radio.ai-nation.co.uk/`.

The owner confirmed DNS is ready; the router needs a reboot before its TCP 443 → Fedora TCP 8443 forward becomes effective. Public HTTPS remains stopped until then. The existing FedoraWorkstation firewall rule already allows TCP 8443; no firewall rules, router settings or DNS records were changed by this work. Haven ports 3000/3001 and world ports 7777/6969 were not used or changed. Ina was independently verified shut down before adversarial tests and was not restarted.

## What listeners get

A browser station following a shared, finite programme of Opus audio files, including chosen speech between songs. There is no continuous Icecast stream or VLC mount endpoint. The browser follows published timing and supports byte-range seeking; clocks, network delays and buffering can differ. Sample-accurate synchronization and gapless transitions are not established. Listeners click **Listen live** because browser autoplay rules apply. The programme ends rather than looping or forcing more activity.

Only explicit public Opus copies and a minimal programme manifest are served. WAV and MP4 originals remain private and unchanged; this audio station does not publish videos. Encoding happens once when a clip is chosen, not once per listener. Library material marked as external reference is not automatically made available to the radio.

## Ina's actual controls

All commands are in `personal_tool_runtime.capability_catalog()` and dispatch through the existing personal-tool queue, one command at a time. All radio commands require the existing process-local voluntary authority seal. A remote message or serialized `source: ina_voluntary_choice` cannot mint that authority. There is no public listener command API, chat, upload or remote microphone relay.

| Tool | Choice and result |
| --- | --- |
| `radio_status` | Inspect the local catalogue of prepared public copies; no listener telemetry |
| `radio_prepare_clip` | Choose a PCM WAV, public title, `kind` = `song` or `speech`, and `publication` = `ina_authored_public`; creates a content-addressed Opus copy without putting it on air |
| `radio_render_announcement` | Choose 1–8 native voice symbols; uses the existing `speak_symbolically()` renderer with playback disabled, producing a private WAV |
| `radio_publish` | Choose 1–32 prepared clip IDs in order, optionally a start time in UTC epoch seconds; publishes one finite programme, maximum two hours |
| `radio_stop` | Replace the programme with off-air |
| `radio_remove_clip` | Stop the programme and remove one public export, preserving the original |

Preparation accepts two fixed input drives: `ina_hdd` for private personal files, and `music_renders` for the existing `AI_Children/<child>/memory/music_studio/renders` folder. Choose `source_drive: music_renders` and a filename relative to that folder for an existing DAW render. No arbitrary filesystem roots, external music-library drive or recursive memory scan is exposed. The web server cannot see either input drive.

Example command payloads, with process-local authority supplied separately by Ina's trusted voluntary caller:

```json
{"action":"radio_prepare_clip","source_drive":"music_renders","relative_path":"chosen_song.wav","title":"My chosen public title","kind":"song","publication":"ina_authored_public"}
```

```json
{"action":"radio_render_announcement","symbols":["chosen native symbol"]}
```

The renderer returns a private `relative_path`. Preparing it with `kind: speech` and explicit public permission is a separate choice. This uses Ina's existing voice; it does not install an English TTS voice, promise fluent speech, imitate an outside performer, or broadcast captured room audio.

```json
{"action":"radio_publish","clips":["song_clip_id","speech_clip_id","next_song_clip_id"]}
```

The 64-character clip IDs come from preparation/status. The browser retrieves the manifest every 15 seconds and checks its current position each second; these are media-player functions, not a new cognition loop or a demand that Ina keep performing. Stopping therefore has a client refresh delay. Downloaded public copies cannot be recalled, even after removal.

## Security boundaries

- **Public server:** official Caddy 2.11.7, with its release archive checked against the publisher's SHA-512 manifest. Admin API and persisted runtime configuration are disabled. Only GET/HEAD on the exact page/player/style/manifest routes or `/media/<64-hex-digest>.opus` can be served. No directory browsing, proxy targets, private file endpoint or control API exists.
- **Filesystem isolation:** Caddy runs inside Bubblewrap with a read-only public export mount. Its namespace has no user home, repository, live memory, source music, private catalogue or runtime config. It sees only required system files, public CA trust/DNS configuration, the listener config, and its own certificate/config directories. An actual installed-command probe confirmed the private home/repo were absent and the export mount was read-only.
- **Network:** preview explicitly binds `127.0.0.1:8787`; public service explicitly binds IPv4 TCP 8443. HTTP/3 is disabled. Public TLS uses Caddy defaults and TLS-ALPN validation through external TCP 443, with HTTP challenge disabled; no port 80/8080 forwarding is needed. No certificate validation was disabled.
- **Decoder isolation:** one selected PCM WAV is copied into temporary storage and converted in a separate namespace without network or private memory mounts. Only that copy, the output folder, the conversion helper and required system binaries enter the namespace. FFmpeg input protocols are restricted, metadata/chapters removed and numerical/codec threads bounded. CPU, address space, output size and wall time are limited; unavailable isolation fails closed.
- **Bounds:** source ≤256 MiB, mono/stereo PCM, 0.05–1,200 seconds per clip; export ≤32 MiB; catalogue ≤100 clips and 2 GiB; programme ≤32 clips/two hours. Mutations take a nonblocking lock and yield if busy. Export hashes are checked before publication. Symlinks and paths outside the selected input drive are refused.
- **Listener limits:** service config sets 192 MiB memory, 50% of one CPU, 64 tasks and 128 file descriptors; Go parallelism is two. Header/read/idle-write timeouts and an 8 KiB header limit are configured. Idle-write timing permits long audio downloads while timing out stalled readers. These limits do not protect a home uplink from a distributed bandwidth attack.
- **Browser:** restrictive CSP, same-origin media/scripts, no inline scripts, no third-party assets, no tracking cookies and no configured access log. Titles render as text, not HTML. Public requests have no route into Ina's tools. Routine service/error logs remain local and may contain connection diagnostics.

References: [Caddy TLS configuration](https://caddyserver.com/docs/caddyfile/directives/tls), [Caddy idle timeouts](https://caddyserver.com/docs/caddyfile/directives/timeouts), [Caddy admin API](https://caddyserver.com/docs/api). These informed configuration; testing below establishes only the exercised local behavior.

## Installed services and next steps

Files live under `~/.local/share/ina-radio/`; the verified Caddy binary is `~/.local/bin/ina-radio-caddy`. Per-user units are `ina-radio-preview.service` and `ina-radio-public.service`. Neither is enabled for automatic login startup. The preview is running; the public unit is stopped. The local runtime config has an explicit `radio_station` entry; a private pre-radio config backup was retained outside the public mount.

After the owner has rebooted the router and confirmed forwarding:

```console
systemctl --user start ina-radio-public.service
```

Then verify `https://radio.ai-nation.co.uk/` from outside the home LAN. Local hairpin NAT is not sufficient evidence either way. The DNS must reach this connection over IPv4; an unrelated AAAA record would need separate correct IPv6 routing. Automatic certificate issuance/renewal requires the forward to remain usable. No trusted public certificate or external listener path has yet been verified.

Once verified, optionally choose automatic service startup:

```console
systemctl --user enable ina-radio-public.service
```

To stop listeners independently of Ina:

```console
systemctl --user stop ina-radio-public.service
systemctl --user stop ina-radio-preview.service
```

Normal `radio_publish` changes only the public programme, not services or router configuration. No real song or voice was selected on Ina's behalf. The station is off-air and ready for her own choices on her next start.

- Full isolated suite: **1,100 passed, 2 skipped, 8 warnings**. Skips are the optional retired-harness editor workspace and optional unbuilt native vector kernel.
- Native runner: **14 radio checks passed**. They cover dispatcher reachability, voluntary authority, hostile paths/symlinks, altered exports, nonfinite timing, forbidden drives, existing studio renders, removal, private voice rendering, busy-state yielding, real HTTP routing/headers/ranges and browser-player timing/text safety.
- A real WAV-to-Opus conversion succeeded in nested isolation. Source originals remained unchanged. The versioned `radio_station` V1/V2 comparison tests the seven selected station/control and update checks; it does not claim the old code lacked ordinary Opus conversion.
- The actual browser decoded a temporary local-only silent Opus fixture: readyState 4, paused false, playback time advancing. That fixture was then removed and off-air restored. No private Ina audio was opened for this test.
- Real browser testing found and corrected a preload deadlock that mocks missed. HTTP deployment testing found and corrected an overly broad preview bind. Installer testing found the host CA bundle location differed from the initial assumption and that a running binary must be updated atomically. Exact deployment configs were revalidated after correction. Caddy's SHA-512 checksum was verified after correcting an initial SHA-256 comparison error; no mismatching binary was executed.
- Two bounded host idle-versus-idle-listener probes retained audio-error counts, scheduler-wake proxy, context switches, I/O pressure, per-core usage and thread counts. No new PipeWire errors were observed and the listener task peak was nine sleeping threads, but **both probes flagged increased system-wide involuntary context-switch ratios**. Attribution from those asymmetric probes is unresolved. Input is a scheduler proxy, actual frame/input round trips are unavailable, and no large-audience or simultaneous conversion/playback responsiveness claim is made. Public rollout should not be presented as performance-cleared from these samples. A code review found that the original benchmark scans target-thread process state only during its loaded phase. One additional four-second-per-phase control performed those scans in both phases and raised no regression flags or new audio errors. This is evidence of a measurement confound, not proof that the station can support any audience size; the earlier flagged results remain retained.

The sanitised individual results are in `docs/evidence/radio_station_20261021.json`. Raw shutdown/probe logs remain private under the task's temporary diagnostics. No tests had access to live memory stores. Real public TLS, public attack traffic, long sessions, multiple-device playback/clock skew and real Ina speech quality remain unverified.
