# Revisable intuition: implementation and limits

Intuition may justify attention without certifying truth. It need not arrive with
an explanation. The optional `intuition_inquire` personal tool reuses the existing
self-inquiry journey: an explicit question, an error-checking proposal and a
witness reference initiate one stage by default (at most five). These are evidence
requests, not automatic retrieval, code execution or external-access permission.

`intuition_review` accepts candidate revisions, supporting and opposing evidence
references, and stop/remain-uncertain choices. Earlier candidates survive in a
bounded revision history; no numerical confidence is presented as calibrated.
References are caller-provided, not verified independent witnesses. This is an
investigation scaffold, not a demonstrated intuition learner or truth adjudicator.
No spontaneous hunch logging, forced explanation or custom-memory changes added.

Fixed in the shared journey: terminal decisions cannot be reopened by its update
function; duplicate references and hypothesis iterators have admission budgets;
omitting a revision no longer clears candidates; nonfinite confidence is rejected.
Callers can explicitly choose a new inquiry. Pure returned records are not sealed
execution capabilities, and modifying one grants no execution authority.

Benchmark V3 is registered alongside retained V1/V2. The standalone comparison
uses source extracted from `0bc84c5`, and separates terminal behavior, candidate
preservation, counterevidence, iterator bounds and non-authoritative status.
Live calibration, investigation quality and cross-domain learning are unmeasured.
